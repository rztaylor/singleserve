# v0.1 API specification

Status: **Released in v0.1.0**

This document is the normative contract for v0.1.0. Public examples compile as tests. Consumer validation is complete through two public-API harnesses. A real-browser smoke run remains conditional on a supported browser and stable harness; it does not change this contract without a reviewed spec update.

## Goals

v0.1 must let a Go application provide an `http.Handler`, start it safely on loopback, open an authenticated browser URL, track browser tabs, choose an explicit or browser-bound lifetime, reject unsafe shutdown, and stop gracefully. It must also provide a frontend-neutral JavaScript client for authentication, heartbeats, disconnection, health failure, and shutdown requests.

## Public Go surface

The only public package is `github.com/rztaylor/singleserve`.

```go
const (
    TokenHeader = "X-Singleserve-Token"
    TabHeader   = "X-Singleserve-Tab"
    ControlPath = "/_singleserve/"
)

type Options struct {
    Handler  http.Handler
    Address  string
    Lifetime LifetimePolicy
    Guard    ShutdownGuard
    Opener   BrowserOpener
}

func New(Options) (*Server, error)

type Server struct { /* unexported state */ }

func (s *Server) Start(context.Context) (*Launch, error)
func (s *Server) Tabs() []TabSnapshot

type Launch struct { /* unexported state */ }

func (l *Launch) Address() string
func (l *Launch) BaseURL() string
func (l *Launch) URL() string
func (l *Launch) OpenBrowser(context.Context) error
func (l *Launch) Shutdown(context.Context) error
func (l *Launch) Wait() (Result, error)
```

### Construction and startup

- `Handler` is required and must be non-nil.
- Empty `Address` means `127.0.0.1:0`.
- `Address` must resolve syntactically to `localhost` or an IP loopback address. Empty hosts normalize to `127.0.0.1`; wildcard, interface, and other hostname binds fail before listening.
- A `Server` is single-use. A second `Start` call returns a stable error satisfying `errors.Is(err, ErrAlreadyStarted)`.
- `Start` binds before returning and starts serving the wrapped handler. `Launch.Address`, `BaseURL`, and `URL` never contain port `0`.
- `URL` contains the launch token as the `singleserve_token` query parameter. `BaseURL` never contains it.
- `OpenBrowser` is explicit and may be called zero or one times by the consumer. Its failure does not stop the listener.
- `Shutdown` is an owner-forced graceful shutdown and bypasses `ShutdownGuard`, like parent-context cancellation.
- `Wait` may be called more than once and blocks until drain completes. Normal shutdown returns a `Result` and nil error; listener, serving, or drain failures return the best available `Result` plus an error.

## Lifetime policy

```go
type LifetimeMode uint8

const (
    LifetimeExplicit LifetimeMode = iota
    LifetimeBrowserBound
)

type LifetimePolicy struct {
    Mode                LifetimeMode
    FirstContactTimeout time.Duration
    HeartbeatTimeout    time.Duration
    DisconnectGrace     time.Duration
    CheckInterval       time.Duration
}

func ExplicitLifetime() LifetimePolicy
func BrowserBoundLifetime() LifetimePolicy
```

`ExplicitLifetime` is the zero-value/default policy. Browser health is still tracked, but absence never initiates shutdown.

`BrowserBoundLifetime` returns these initial defaults:

- first contact: 2 minutes;
- heartbeat timeout: 15 seconds;
- disconnect grace: 5 seconds; and
- lifecycle check interval: 1 second.

For a custom browser-bound policy, `HeartbeatTimeout` and `CheckInterval` must be positive. A zero `FirstContactTimeout` disables that deadline, and a zero `DisconnectGrace` requests shutdown immediately after the last tab disconnects or expires. Negative durations are invalid.

Browser-bound rules:

1. If no tab contacts the process before a configured first-contact timeout, request shutdown with reason `ShutdownFirstContactTimeout`.
2. A tab is connected from its first valid heartbeat until explicit disconnect or heartbeat expiry.
3. After at least one contact, if no connected tabs remain continuously through the disconnect grace, request shutdown with reason `ShutdownBrowserDisconnected`.
4. New contact during the grace cancels the pending automatic shutdown.
5. A typed guard denial keeps the process alive. The policy retries while the absence condition remains true.

Opening a browser and choosing browser-bound lifetime are independent. This permits manual startup with browser-bound lifetime and browser opening with explicit lifetime.

## Shutdown contract

```go
type ShutdownReason string

const (
    ShutdownBrowserRequest      ShutdownReason = "browser_request"
    ShutdownBrowserDisconnected ShutdownReason = "browser_disconnected"
    ShutdownFirstContactTimeout ShutdownReason = "first_contact_timeout"
    ShutdownProgrammatic        ShutdownReason = "programmatic"
    ShutdownContextCanceled     ShutdownReason = "context_canceled"
    ShutdownServerError         ShutdownReason = "server_error"
)

type ShutdownRequest struct {
    Reason ShutdownReason
    Tabs   []TabSnapshot
}

type ShutdownGuard interface {
    CheckShutdown(context.Context, ShutdownRequest) error
}

type ShutdownGuardFunc func(context.Context, ShutdownRequest) error

func (f ShutdownGuardFunc) CheckShutdown(context.Context, ShutdownRequest) error

type ShutdownDeniedError struct {
    Code    string
    Message string
}

func DenyShutdown(code, message string) error
```

- Nil guard means allow.
- The server constructs `ShutdownRequest`; its tab snapshot cannot be supplied by a browser or application request.
- A `ShutdownDeniedError` means a safe, expected veto. Code must match `[a-z][a-z0-9_]*`; message must be non-empty.
- Any other guard error is an internal guard failure. It prevents shutdown but is not exposed verbatim to the browser.
- Browser requests and browser-bound policy evaluate the guard.
- Parent-context cancellation and `Launch.Shutdown` bypass it so the owning process can always terminate.
- Guard callbacks must be concurrency-safe, must honor context cancellation, and must not mutate toolkit state.

Graceful shutdown stops accepting new connections, drains through `http.Server.Shutdown` with a default five-second deadline, then closes idle resources. Concurrent requests are idempotent; the first accepted reason is recorded in the result.

```go
type Result struct {
    Reason    ShutdownReason
    StartedAt time.Time
    StoppedAt time.Time
}
```

## Tab snapshots

```go
type TabState string

const (
    TabConnected    TabState = "connected"
    TabDisconnected TabState = "disconnected"
    TabExpired      TabState = "expired"
)

type TabSnapshot struct {
    ID             string
    State          TabState
    ConnectedAt    time.Time
    LastSeenAt     time.Time
    DisconnectedAt time.Time
}
```

`Tabs` returns a time-ordered copy and never aliases mutable internal state. IDs are validated as 128-bit-or-stronger URL-safe values with a bounded length. Recently disconnected records may be pruned; snapshots are operational state, not an audit log.

## Browser opener

```go
type BrowserOpener interface {
    Open(context.Context, string) error
}

type BrowserOpenerFunc func(context.Context, string) error

func (f BrowserOpenerFunc) Open(context.Context, string) error
```

The default opener starts, but does not wait for, the platform command. It supports:

- macOS: `open`;
- Windows: `rundll32 url.dll,FileProtocolHandler`;
- Linux: WSL-aware fallbacks, then `xdg-open`, `gio open`, and `sensible-browser`.

Command lookup/start are injected internally for tests. A URL is passed as one argument and never through a shell.

## Authentication and HTTP composition

Singleserve wraps the application handler with authentication and reserves `/_singleserve/`. Application registration under that prefix is unsupported and unreachable.

Authentication is satisfied by exactly the current launch's:

- `X-Singleserve-Token` header;
- `Authorization: Bearer <token>` header;
- launch-unique session cookie; or
- `singleserve_token` query value on `GET` or `HEAD` only.

A valid query bootstrap sets a cookie whose name is unique to the launch, with `Path=/`, `HttpOnly`, `SameSite=Strict`, no persistent expiry, and `Secure=false` because v0.1 is loopback HTTP. Token comparison is constant-time. Missing or invalid authentication returns 401. Authentication failures do not reveal whether a token was close or stale.

Singleserve consumes its own token query value, token header, matching bearer credential, and launch cookie before delegating to the application handler. Unrelated application cookies and authorization are preserved. This keeps capability material out of ordinary application logs and middleware.

Unsafe requests with a browser `Origin` must match the launch origin. Singleserve does not add CORS allowances. Consumers that need non-browser programmatic access use the token header and omit `Origin`.

## Reserved HTTP endpoints

All responses are JSON except the client module, are authenticated, and include `Cache-Control: no-store`.

| Method | Path | Success | Purpose |
| --- | --- | --- | --- |
| `GET` | `/_singleserve/health` | 200 `{"ok":true}` | Authenticated liveness without changing tab state |
| `POST` | `/_singleserve/tabs/heartbeat` | 200 | Mark the `X-Singleserve-Tab` tab connected/seen |
| `POST` | `/_singleserve/tabs/disconnect` | 200 | Best-effort explicit disconnect for the tab header |
| `POST` | `/_singleserve/shutdown` | 202 | Guarded browser-requested graceful shutdown |
| `GET` | `/_singleserve/client.js` | 200 JavaScript | Canonical ES-module browser client |

Heartbeat or disconnect without a valid tab ID returns 400. A shutdown denial returns 409:

```json
{
  "ok": false,
  "error": {
    "code": "work_running",
    "message": "Wait for the current operation to finish"
  }
}
```

Unexpected guard errors return 500 with code `shutdown_guard_failed` and a generic message. Unsupported methods return 405; unknown reserved routes return 404.

## Framework-neutral browser client

The canonical `client/singleserve.js` source is a dependency-free ES module and is also served byte-for-byte by the control endpoint.

```js
import { connect } from "/_singleserve/client.js";

const session = await connect({
  onServerUnavailable: () => showRecoveryUI(),
});

const response = await session.fetch("/api/items");
await session.requestShutdown();
session.stop();
```

`connect(options)`:

- reads `singleserve_token` from the current URL or tab `sessionStorage`;
- stores a URL token in `sessionStorage` and removes only that query parameter with `history.replaceState`;
- creates a cryptographically random tab-instance ID;
- performs an immediate heartbeat, then one every five seconds;
- gives each heartbeat a two-second abort timeout;
- calls `onServerUnavailable` once after three consecutive failures;
- calls optional `onHeartbeat` after every completed heartbeat with `{ok, failures, tabID, checkedAt}`; callback failures do not interrupt lifecycle scheduling;
- sends a best-effort authenticated keepalive disconnect on `pagehide`; and
- returns an object with `fetch`, `health`, `requestShutdown`, `disconnect`, `stop`, `token`, and `tabID`.

Tests and advanced integrations may override `heartbeatIntervalMS`, `heartbeatTimeoutMS`, and `failureThreshold` with positive numeric values. These timing options do not change server policy.

`session.fetch` preserves caller headers, adds token and tab headers, and never retries application requests. `stop` is idempotent and stops timers/listeners without requesting process shutdown. The client makes no DOM assumptions beyond browser platform APIs and renders no UI.

## Acceptance criteria

Implementation is accepted only when all of the following are true:

Release validation: `scripts/check.sh` covers automated Go, security, lifecycle, opener, client, race, vet, format, documentation, and coverage gates. `TestBrowserBoundConsumerHarness` and `TestExplicitConsumerHarness` exercise two materially different consumer shapes entirely through the public API. No supported real browser is installed in the release environment, so the two-tab browser smoke is an explicit v0.1.0 skip; the residual risk is browser-engine behavior around bootstrap, page close, and terminal recovery UI.

### Hosting and API

- The module builds with Go 1.26 and has no third-party runtime dependencies.
- `Start` assigns a usable random loopback port before returning.
- IPv4, IPv6 loopback, `localhost`, and empty-host normalization have focused tests; wildcard and non-loopback cases are rejected.
- The supplied handler serves unchanged behind the wrapper outside the reserved prefix.
- Public examples compile as tests.

### Authentication and security

- Tokens contain 256 bits from `crypto/rand`; injected deterministic token generation is available only to tests/internal code.
- Header, bearer, cookie, and safe-query bootstrap variants are tested.
- Unsafe query-token use, invalid tokens, cross-origin unsafe requests, permissive preflight, cookie collision across two simultaneous launches, cache headers, and token non-echo are tested.
- Race-enabled tests cover concurrent auth, startup, and shutdown paths.

### Tabs and lifetime

- Two tabs heartbeat independently; disconnecting or expiring one does not stop a browser-bound server while the other remains connected.
- Explicit disconnect and heartbeat expiry produce distinct snapshots.
- First-contact timeout, disconnect grace cancellation, all-tabs-gone shutdown, explicit lifetime non-shutdown, and guard-denied retry are deterministic under an injected clock/ticker boundary.
- Tab IDs and retained tracking are bounded against malformed input and unbounded growth.

### Shutdown

- Browser shutdown returns only after the denial/acceptance response is writable.
- Typed guard denial, unexpected guard failure, context cancellation, forced owner shutdown, duplicate requests, and serve/drain errors are tested.
- Application handler requests in flight are allowed to complete within the drain deadline.
- `Wait` reports the winning shutdown reason without races.

### Browser integration

- Browser opener command selection and fallback are unit tested for macOS, Windows, Linux, and WSL without launching real programs.
- Client tests cover URL scrubbing, `sessionStorage` fallback, header merging, immediate/periodic heartbeat and observation, consecutive failure reset, one-shot unavailable notification, pagehide disconnect, shutdown denial payloads, and idempotent stop.
- The served module equals the canonical source.
- When a supported browser and stable harness are available, a browser smoke test proves token bootstrap, asset loading, two-tab tracking, one-tab close survival, final-tab shutdown, and explicit-policy survival.

### Repository gates

- `go run ./examples/minimal` is an executable specification that imports only the public API; CI builds it and smoke-tests bootstrap, the application endpoint, heartbeat, and browser shutdown without requiring a real browser.
- `scripts/check.sh` passes, including the example build/smoke, `go test`, `go vet`, formatting, docs checks, and race tests.
- Overall Go statement coverage is at least 80%; auth, tab tracking, and shutdown packages/files have meaningful focused coverage rather than coverage-only assertions.
- README, package docs, migration guide, changelog, decisions, and release governance match implemented behavior.
- Two representative repository-owned compatibility harnesses validate the public API: browser-bound final-tab shutdown and explicit lifetime with a guarded browser shutdown request.

## Explicit deferrals

- remote listeners, TLS, proxy headers, and LAN mode;
- WebSockets, service workers, and background sync;
- npm publishing or a TypeScript package;
- configurable control prefixes, auth header names, query names, or cookie policy;
- persisted sessions or reconnecting to a restarted process;
- application job registries, recovery stores, locks, or transactions;
- automatic browser opening inside `Start`; and
- compatibility aliases for application-specific endpoint or header names.
